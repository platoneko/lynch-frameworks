# 框架契约 — 写作细则（懒加载）

`frameworks/AGENTS.md` 的写作细则部分：写或改标的文档、轴文件之前读。核心契约（真源、林奇分类、五档价带、现价禁写的核心、落盘门闩）仍在 `frameworks/AGENTS.md`；那里保留同名小节作路标，存量「`AGENTS.md「…」`」指针照旧有效。

## Ticker 文件名

**Ticker 文件名**：美股 **MUST** 带 `.US`（`<代码>.US`）；港股/A 股保留市场后缀（`.HK` / `.SH` / `.SZ`）。文件名 = 题头 `# TICKER` = `frameworks/eval/<TICKER>.py`；与 Longbridge 等多市场符号对齐。细则见 skill `sediment-framework`。

## 框架文档

- 题头（`#` 下两行引用块）：第一行林奇类 / 更新日期 / eval 路径；第二行 `主尺：…` 用一句话让读者看懂采用的估值方法。
- **更新日期 = 最近一次落盘的当天**（2026-10-30 定）：任何模式落盘（初建、事件增量、框架纠正、题头修补）都 **MUST** 把题头 `更新：` 改成落盘当天。app 拿它判断框架是否在上次财报之后更新过（文档页与首页「财报后未更新」、财报页「已调研」），漏改会让刚处理过的财报一直显示未更新
- 未挂共享情景轴的票可在人读文档解释自身卖方共识落在哪一档；机器显示所需的自身共识放在脚本结果 `own_consensus`，使用合法档位 `tier` 和 `YYYY-MM-DD` 格式的 `as_of`。来源性质 `kind` 为 `historical` 或 `single_institution`，后者须提供非空 `institution`；来源限制可用简短 `source_note`。未知时不构造有效共识，也不能从正文题头提取。仅挂同业尺仍可保留自身共识；共享情景轴的定档 / 参照处理见下文。当前 `just check` 不负责提示正文中的共识是否被轴遮蔽。
- 更新时间线保留在同一文件；仅**引用的客观数字有变化**时新增记录，写明旧值、新值、来源、日期及估值影响；卖方预测或公司指引标明为预测。初建、算法纠错、规则调整、文字修改以及财报核对但引用数字未变时不新增记录。历史中记录客观数据变化的内容保留；纯算法或规则纠错按用户要求移至脚本注释，不作为数据更新记录。
- 财报实际已披露时及时更新可用输入并重算；卖方尚未更新时注明预测的来源日期，不因此沿用所有旧财报输入。不能核实的资金用途、业务归属等明确列为待核，条件试算不能冒充正式估值。
- 文档面向读者，首先展示采用最新可用财报实际后算出的结果及其正式、候选或条件状态；预测仍旧时标出来源日期，不把尚未选择的条件当正式估值。旧基准只在帮助理解变化时简短交代日期及区别，不作为正文焦点。分部资料不足时说明整公司估值，不虚构可分部核实的贡献。
- 三档构造用表格按业务或估值部分列出保守、中性、乐观各自的每股贡献及合计；若某部分无可靠拆分，用整公司结果说明。每部分用口语解释实际估值方法，并把每档实际使用的长期折现率、长期增长率、前瞻回报和成熟回报并列展示；各档相同可重复列示，不同须分别列值。某档使用账面等另一方法时，先交代该档实际依据，不在盈利模型参数表里用一排「不适用」掩盖其构造。对影响档位的利润预测、资产折价等关键数字也给出来源、日期和预测或判断性质。
- 参数表逐档核对脚本计算后实际使用的值，不把共享参考或录入的未调整值直接当作各档结果。例如某档成熟回报受该档前瞻回报约束时，表中填该档约束后的数，并另说明共享参考及采用原因；未参与该方法计算的参数不要编造。脚本输出缺少可供核对的实际值时，先补充数值输出并重算；未核实前不得声称参考值就是采用值。
- 读者的阅读顺序是：估值结论及状态 → 三档贡献和实际使用的参数 → 各档对应的业务情景 → 值得关注的证据和估值传导；候选或新业务价值、最重要的敏感性在相关位置补充。用短段落说明每部分采用的估值方法、关键来源及推算的大致路径，让读者知道估值依赖什么。正文只保留有助于判断结论的数字、理由与证据缺口；完整输入表、中间数、逐步演算、公式推导、拟合及插值放在脚本和注释，不能把脚本注释整段搬进正文。旧记录中的客观数据和可追溯来源仍须保留。
- 文档注明共享参考与采用值及来源。观察事项只选对估值影响大、值得读者判断的事项；每项说明新证据会影响哪个输入或模型、涉及哪些档位、是否已计入，并区分脚本直接计算、需要研究者判断后调整及目前未计价。能在同一基准下解释幅度的，说明改变了什么及其他不变条件；证据不足以量化时如实说明。敏感性同样只挑选影响大且值得判断的参数。
- 更新记录让读者看到引用数据发生了什么变化及其估值影响：同一事件的相关变化合并表述，简明列旧值、新值及来源；多项输入同时变化时只说明合计影响，不能把差额归因于其中一项。具体计算步骤保存在脚本注释，不把更新记录写成演算日志。
- 分部利润、资本、费用或可比倍数没有直接预测时，先利用可核对的财报、公司指引和卖方资料建立有依据的估算：明确使用的数据、时间、推算关系、口径桥和各档假设，并把推算逻辑与来源写在脚本注释，正文用通俗语言解释。研究估算可用于情景，不得标成公司实际或卖方共识；不能把没有直接披露当作自动停止计算的理由。估算涉及互相重叠的业务、资产、现金或成本时须逐项去重；缺失值不能静默当零。数据或口径不能合理推算时，保留缺口并给能支撑的条件比较；命中明确的财务阻断仍按相应规则处理。
- 采用的分部推算若可由脚本内已有的销量、价格、毛利、费用等输入重建，脚本应直接从这些输入计算中间结果，让调整假设后结果随之重算；不要把同一推算结果另抄为独立常量。外部直接提供的预测是输入，不能伪装为脚本推算；推算和外部预测各自记录来源及日期。
- 默认允许个股有依据地偏离共享的增长率或回报率参考；脚本记录参考、采用值与理由，正文标明差异，不因此更改其他个股。折现率仍按既有篮子规则，除非另获明确决定。
- 引用规则版本（框架与每票演算同）：写规则名 + 日期，如「valuation-rules 裁决表 ② / 两段式过渡，2026-09-21」；**MUST NOT** 写 git 提交哈希——历史重写（2026-09-26 拆仓的 `filter-repo`）会让哈希失效

## 篮子声明 — 行契约

**篮子声明**：脚本对每条实际用于估值的折现率声明篮子与理由，以 `gordon.check_r` 校验；只作披露的读数不冒充篮子值。正文展示采用值及读者需要的依据，不作为解析来源。

## BLOCKED 只在落盘前

**BLOCKED 只在落盘前**：规则拦下 = 停下来向用户报告具体原因；泛授权不能解除。用户看过原因仍明确拍板时，记录未满足的规则、判断和复核条件；数值检查和数学上不可计算的情况不能因授权被伪装为成功计算。

## 超额现金 — 行契约（2026-10-13 定）

超额现金是否单列、可分配部分及增长资金缺口按 `rules/retention.md` 判断。脚本保存计算口径、来源与归母份额并防止重复计价；正文解释影响估值的现金判断及尚未核实的用途，不要求固定演算行。

## 未建模期权（\(V_{opt}\)）— 行契约

新业务潜在价值与正式基础估值分开；脚本输出价值、各档计入后的估值，正文解释成立条件、重复计价风险与兑现比例。比例是情景设置时不得称为统计概率。不要求为每条带重复五档表。

## 共识升级候选带（candidate）— 行契约

候选带与正式基础估值分开，脚本输出三档及简短标签；正文说明其来源、成立条件及何时重议。候选带不得冒充已采用的正式带。

## 资金用途候选区间（研究披露，2026-11-05）

同一盈利情景的资金用途或释放期限无法判断时，按 `rules/retention.md` 同名节说明采用条件、受影响档、证据缺口与条件试算；公式与完整输入留在脚本。条件试算与正式带、共识升级候选带分开；不把特定条件比较说成全部不确定性的上下界。旧正式锚点保留时写旧基准及未解决的资金假设。校验同基、连续性、有限期折现及与正式锚点隔离。

## 共享情景轴

本节保留共享情景及挂载的业务语义。新版计算的共享数值、来源与挂载信息以机器模块和结果为准；轴正文供研究者阅读和质疑，**不从正文**提取计算输入、结果或机器挂载关系。迁移和消费链尚未覆盖的部分标待补，不回退旧正文解析。

**共享情景轴**：多票落在同一条宏观或产业驱动因子上时（金铜价格梯、AI capex 路径、利率路径…），**MUST** 共用同一条情景梯；各票通过 `DEPENDENCIES` 声明并由统一入口传入同一机器轴数据，校验实际使用的映射和约束，不再从各票正文复制数值逐格对账。各票只保留自己对该梯的**敏感度**，**MUST NOT** 各造各的下行。

轴的量化真源为 `frameworks/axes/<轴模块>.py`，其中记录共享数值、来源、日期、口径及判断。个股的 `DEPENDENCIES` 显式指向模块并可声明轴选项；统一入口调用模块的 `inputs(ticker, **axis_options)`，只从返回字典的 `axis_metadata` 采集类型和身份，并将轴快照传给个股、在 `source_versions` 记录实际来源版本。`frameworks/axes/<轴名>.md` 是不进标的池的人读说明，解释各档含义、依据、传导规则和约束；稳定引用仍可写逻辑 id `` `_AXIS.<轴名>` ``。已声明的机器模块缺失时统一入口报错，不产生该次可用计算结果；已有已保存价带按其来源状态处理。模块存在且计算可完成、但展示元数据或类型缺失时，保留可读取的价带并将轴资料标待核；不能把它当成确定无轴，也不把文档当回退接口。

新版情景轴要供首页识别，轴模块返回的 `axis_metadata` 须含：`axis_id`、与之对应的 `logical_id`、`axis_type`（取值 `shared_scenario_axis`）、非空 `title` 与 `label`、本票 `role`，以及 `priced_mounts` / `reference_mounts` 两个成员列表。两列表不得重叠，本票必须属于与 `priced` 或 `reference` 角色对应的列表；同一轴各票的名称应一致。跨轴约束或候选样本不得冒认为定档。数据未知不编造；已有来源但字段缺失 / 类型未知时保持待核。`rates_axis` 和 `peer_ruler_axis` 当前不进入首页情景轴筛选，未覆盖类型按现状待核，不从正文推断身份。怎么造见 skill references「共享情景轴」。

**历史参考与共识**：人读轴文档应解释参考位置、依据和日期；机器轴的 `axis_metadata` 在有依据时记录 `historical_consensus`，其 `band` 为 `L`、`M`、`H`、`L-M`、`M-H`、`<L` 或 `>H`，`as_of` 为 `YYYY-MM-DD` 来源日期。单家预测以 `kind: single_institution` 和 `institution` 标明机构；转述与其他来源限制用简短 `source_note` 保留。不得编造或含任何票的现价；未知则留空，不从题头猜测。新版消费者从已保存结果的元数据读取，历史补充材料与旧估值的关联未核实时须明示；未覆盖的轴与消费者保持待补，`rates_axis` 不作情景轴筛选。

**定档 / 参照挂载（2026-10-02 定）**：轴的共识只代表**定档**挂载票；机器轴声明定档 / 参照成员及当前票角色，人读文档说明差异。新版情景轴展示对参照关系不继承共识档。判据是**轴的档位能否对应到票的同一档**：

- **定档**：轴的 L/M/H 一一对应本票的 L/M/H——轴值进三档分子或倍数，或本票明示逐档映射（如 L←α · M←β · H←γ）。只经 SOTP 一条腿也算，但该腿占本票 M **< 1/4** 时改判参照。
- **参照**：轴值只被引用、跨文件校验、报隐含份额，或只喂 \(V_{opt}\) / 候选带，或只驱动部分档（如只挂 L 档）；构成方（本身被加总进轴的票）一律参照。

参照票不另写本票共识行（M 的分子按「锚点语义」本就是共识基线，那一行对它是同义反复）；不把轴共识冒充参照票共识。挂新票或改变角色时，按此判据同步更新机器成员关系和人读解释，并检查受影响的已保存结果版本。

## 同业尺轴 — 行契约（2026-10-03 定）

同业尺轴是轴的一种（轴类型 `` `peer_ruler_axis` ``）：情景轴锁「哪个世界」（三档值），同业尺轴锁「同一块业务用同一把尺」——不带三档、不写轴共识、不做加总校验（各票共识加总超出不算矛盾）。**按具体业务（腿）划，不按公司、不按宽泛行业标签**：一条轴 = 一块有共同驱动与共同单位经济的业务（例：硅光晶圆代工；反例：「成熟特种代工」——射频 / 电源 / 传感器各有驱动，只是产能统计口径，不建轴）。一家公司可按腿挂多条。机器模块记录类型及参照成员，正文解释业务范围，逻辑 id `` `_AXIS.<轴名>` `` 保留。个股自身共识保留；当前情景轴投影会跳过同业尺，展示和历史关系未覆盖时标待补，不声称 app 已显示。

研究同业尺 **MUST** 核对：① 组员与各票业务拆法；② 该业务增长率的参考来源和日期；③ 对齐年份；④ 借用过渡年表；⑤ 单位经济及来源层级；⑥ 新业务价值所需的数量与单位；⑦ 镜像关系。共享参考只有一个来源；机器轴保存共享量化数据及来源注释，个股脚本记录轴参考及实际采用值，人读文档解释关键依据，不要求正文保留机器格式。增长率或回报率有依据地采用不同值时记录原因并在正文标注，不把个股采用值误写回共享轴；折现率例外尚未经确认。轴文档 **MUST NOT** 写任何组员现价。

## 现价 — 禁写契约（2026-09-27 定）

**现价 — 禁写契约（2026-09-27 定）**：标的文档（历史更新记录除外）**MUST NOT** 含本票现价及其函数：现行 zone、「现价 → zone」行、市价隐含 r / g / p / \(\delta\)、现价到锚点或切点的距离（P/H、P/L、距切点 %…）、当前市值、当前 PE / PB / 股息率，以及拿现价立论的散文。允许的市场数据（每项 **MUST** 带 as-of）：① 本票**带日期的历史**成交价 / 倍数带（实证坐标、自身实测带护栏、同等盈利月份价、谷底价）——as-of 当日价不算历史；② **他物**市价：汇率、他股 / 同业的价格与倍数（含同业反解 \(g_2\)）、商品价；③ ETF 的 `nav_ref`（与折算所用指数值同一 as-of 日的 ETF 净值）+ 同日指数值。现价 **MAY** 在研究对话里作诊断（A2f 价带偏离反思、隐含 r 对账、\(g_2\) 证据区间门、纠正对账门等），但现价与诊断结论都 **MUST NOT** 落盘。历史更新记录是事件历史，其中带日期的价格与 zone 迁移原样保留。

**机器守卫**：现行 `just check` 用 `frameworks.price_free_violations` 排除可识别的历史记录后扫描部分现价形态，不依赖旧 `§4` 章节边界；它不能证明所有散文都无现价论断，仍需人工审阅。保留历史事实，对面向人的正文不建立依赖固定章节名称的估值解析契约。

## 日报与 \(r_f\) 读数行

日报：`scripts/daily_bands.py` 只读框架锚点 + Longbridge 现价 → 写 `output/bands/` → 飞书（**每天都发**；跨带 `@所有人`）。**MUST NOT** 回写框架 MD。

**\(r_f\) 读数行**：已接利率敏感性的脚本将共识 \(\Delta r_f\) 与反向压力 ±`rf_cap` 的三档写入结构化结果 `rate_sensitivity`，并绑定共享输入及源码版本；日报只读已保存结果中可用的读数，不直接运行模型或读正文。没有读数时日报不显示利率行，字段无效时提示错误；研究中未建币种段 / 未接入 / 无已保存读数须如实说明，不造数。读数不改变底牌锚点、不触发跨带告警，也不进 `_INDEX` 或 `calibration.py`；轴值或锚点变化时须重新计算并按结果发布流程处理，不能把旧结果标为新版本。

## 计算与测试

- 每票脚本拥有实际量化输入、计算过程与来源注释，输出股票、币种、基准日期、基础三档及可选候选短标签和新业务估值；同时输出各业务各档实际使用、需要展示的关键参数数值以及共享参考值，供研究者核对文档。基础三档可以是研究中尚未确认的结果，不能仅凭字段存在就当成正式估值。正文不是输入，也不拼接成长段叙事输出。App 和日报迁移完成后只读取已保存的采纳结果，不直接把任意脚本输出当成已确认结果，也不从正文提取估值。研究 agent 仅在用户明确授权落盘后记录本次采纳结果，并保留对话引用、用户原话与版本；这是本地操作员声明，软件不声称验证了自然语言语义或独立执行证明。具体流程见 `result-publication.md`。
- 面向消费者的 JSON 核心字段固定为 `ticker`、`currency`、`valuation_as_of`、`framework_as_of`、`anchors`、`candidate`、`option`；`anchors` 以 `L` / `M` / `H` 表示基础三档。候选不存在时为 `null`，存在时含简短 `label` 和相同三档结构的 `anchors`；新业务不存在时为 `null`，存在时在其 `anchors` 中提供计入后各档结果。可另给研究所需数值或条件情景，但字段使用稳定标识及数字、布尔、日期等机器数据，候选短标签除外，不拼接来源、判断依据或成段警告。解释、来源、推算方法写在脚本注释和人读文档；必要的失败原因写标准错误。计算结果本身不等于经用户确认的发布结果。
- 交接或模拟所用输入材料须逐项标明单位、年度、税前税后、归母份额、调整口径、来源日期及是真实数据还是估算；只交一组无口径的数字不足以独立回放。缺少某项推算依据时应列为缺口，不得从目标估值或目标分部利润倒推出一项未经记录的假设，以制造结果吻合。已税后化的输入不得再次扣税；企业价值转股东价值时明确所有权、现金及负债的归属，不得隐藏二次换算。情景若依赖未经核实的现金用途，应与已确认基准分开标明条件，不得冒充正式结果或完整上下界。
- 来源和口径的说明供研究者阅读，不能把自然语言说明的字面句子当作程序接口或用逐字匹配决定计算是否通过；可计算的输入和规则使用数值、明确单位及稳定标识进行校验。相同含义的来源说明换一种写法，不应影响估值计算。
- 估值基准日标明财报及计算所对应的时点；研究日期只用于对应的研究和已记录的取值。新的试算或假设不能沿用旧研究日期冒充已确认结果；日期未知时留空或使用机器可识别的空值，并在正文说明实际基准和未确认状态。
- 脚本对适用的阻断条件执行检查；能共用的公式与检查放 `eval/lib/`，各票特有条件留在单票脚本。检查须基于方法的实际适用范围，不能把合理的亏损情景当作无效值，例如成本超过收入时毛利率可以为负；异常值仍须核对来源与业务解释。需要财报或业务证据的判断由研究者核实并说明，程序不能证明事实为真；未确认的试算不得冒充正式结果。
- 测试使用独立核算的固定例子，验证共用方法、每票关键计算和阻断边界；验证输出、确认及消费链路。违规时应失败并说明原因，不能输出可误用的成功结果。不要为每票维护重复公式的复算脚本，也不要用正文排版、编号或具体自然语言句子作为程序输入。
- 共用公式和数据变化须重跑受影响的未归档标的及相关测试，并重新核对此前确认结果；此前确认须绑定脚本、共享代码和数据版本。内容仓 `just check` 读取显式归档清单与来源配置，再检查未归档脚本；缺少必要输入或未运行时如实报告，不能以文档格式检查冒充计算验证。结果是否重新采纳仍按 `result-publication.md` 处理。
