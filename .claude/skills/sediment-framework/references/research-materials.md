# 原始资料：先查本地、按需补缺

## 研究顺序

框架和演算脚本保存现行判断与方法；原始资料库保存判断所依据的披露、研报、网页和原始取数结果。资料入库不代表观点已被框架采纳，资料归档也不是正式框架落盘授权。

1. 读取当前框架中与问题有关的假设和来源。出网前用 `python3 -m eval.lib.research_cli find` 查询已有原始资料；按 `--symbol`、`--period`、`--source-ref` 筛选，需要时加 `--query`。报告期标识按资料登记值查询，不能把年度和季度混用。
2. 资料库由当前项目环境的 `LYNCH_RESEARCH_DIR` 指定绝对路径，或显式传 `--store`。未配置、未初始化、读取失败和零命中分别处理，不创建猜测的默认库，不打印完整环境。
3. 未命中时按已知引用和研究目录做一次有界本地查找：`discover --root <明确绝对目录> --symbol <当前标的>`。它不需要配置资料库，不自动归档。候选只表示文件存在，须读取真实结构核对时期、币种和字段口径；`partial` 表示扫描尚未完成。不能从未命中推断本地不存在资料，不能扫描整个用户目录。
4. 已有资料覆盖的历史期间直接复用，只补缺少的时期。需要确认财报修订、最新预测或口径时，说明补取目的。历史文件的修改时间不能冒充当初取数时间，本地命中也不能证明资料是最新的。
5. 同轮已有完整返回，后续筛字段、排序或排版时处理本地结果，不为加入过滤管道而重新发同一个外部请求。

## 归档和读取

所有成功取得、有价值且与当前假设、输入或行业问题有关的原始资料都应保存，包括最终未引用及反驳当前判断的证据。空结果、错误页面、登录页面和模型自己的总结不当作原始资料。

已有文件：`python3 -m eval.lib.research_cli put --file <文件> --metadata <描述JSON>`。描述必填 `title`、`provider`、`source_ref`、`kind`、`completeness`、`relevance`，以及 `symbols` 或 `topics` 字符串列表。类型取 `filing/report/transcript/webpage/financial_data/search_result`；完整性取 `full/excerpt/search_snippet/unknown`。`report_periods`、`currency`、`published_at`、`fetched_at` 等按已知情况填写，不造时间与口径。

只有工具响应：使用 `put --transcript <精确记录路径> --format claude-jsonl --call-id <调用编号> --metadata <描述JSON>`。app 统一记录及 Claude 原生用 `claude-jsonl`，Codex 原生用 `codex-jsonl`；子线程用 `--thread-id` 消除歧义，多内容块用 `--content-index`。模型只选编号并提供来源描述，正文由程序提取。未经支持的终端格式改用工具提供的文件导出；不能重抄正文冒充原始响应，也不能把工具节选当作提供方全文。

归档结果给出资料编号、来源、版本、原文路径和文本状态。`read <资料编号>` 支持 `--from-line/--to-line` 或 `--page`；大表格扩大相邻上下文。`read <资料编号> --raw-path` 取得原始文件供本地处理。PDF 提取失败仍保留原件，不能把不可搜索当作没有内容。`find` 返回 `has_more/partial/next_offset` 时，按需继续查询，不能把第一页视作全部证据。

资料命令不自行出网或更换身份，原工具仍使用当前目录约定环境。只归档研究资料，不写凭据、登录信息、工具配置和整个聊天。保存失败时说明未归档，原文件保留。正式框架和结果发布仍遵守原有门槛。

## 引用和子代理交接

引用给出原始来源、发布日期及页/行范围，必要时带资料编号；模型推断与原文分开。来源不明时注明，不将替代材料称为已找到原引用。当前框架、规则与轴直接读现行文件，不以库里的旧副本替代。

主代理的派工说明包括：资料库路径、已知资料编号或文件位置、覆盖时期、已做查询、仍缺的证据、任务边界。子代理先复用再补缺，取得新资料后归档，回报编号和关键发现。多个来源复核、不同报告期和口径核对允许继续检索；资料去重不能阻止并发重复下载，不声称全部工具已经自动缓存。
